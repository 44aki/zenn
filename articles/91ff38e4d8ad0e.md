本記事は Rails アプリで「logger と puts 以外の一歩先」に進みたい初心者を対象に、デバッグツールの比較と、debug gem を使用したデバッグ方法を解説します。

## なぜデバッグツールが必要なのか

`Rails.logger.debug` や `puts` を使用したデバッグでは以下のような問題が発生します。

- 並列で API リクエストがあるとログが混ざってしまい見づらい
- 確認したい瞬間の全ローカル変数・スタックなどが抜け落ちる
- 見たい変数の内容を何度も書き換えて再実行するので往復コストが増える

デバッグツールでブレイクポイントを設定することで、任意の行で処理を止めて、変数の内容などを確認することができるためデバッグの時間を大幅に削減することができます。

## ツール比較（debug gem / pry / byebug）

主要な Ruby のデバッグツールを比較

### debug gem（Ruby3 / Rails7 以降の標準）

- Ruby 3.1、Rails 7.0 以降では標準添付されている gem
- `binding.break` コマンドで起動
- 開発が活発
- 他のデバッグツールに比べて高速
- リモートデバッグや VSCode/Chrome デベロッパーツールとの連携が便利

### byebug

- Ruby 3 以前では標準添付されていた gem
- `byebug` コマンドで起動
- irb 上で動作する

### pry-byebug

- byebug を pry 上で動作できるようにした gem
- `binding.pry` コマンドで起動
- byebug の機能に加えて、pry のコマンド群やシンタックスハイライト等が使用可能
- 現在は pry のほとんどの機能が irb でも搭載されており、優位性はなくなった

:::message
現在は Ruby のデバッグツールとしては debug gem 一択。
:::

## 基本的なブレークポイントの設定方法

### 特定の行で止める

コード中に `binding.break` （または `binding.b` ）と入力

```ruby
def calc_total(order)
  binding.b  # ここで停止 (debug)
  order.items.sum(&:price)
end
```

## ステップ操作

ブレイクポイントで止まったあとは以下のコマンドでステップ操作が可能

- `next` / `n`: 同一フレームで次の行へ（ステップオーバー）
- `step` / `s`: メソッド内部へ入る（ステップイン）
- `finish` / `fin`: 現フレームを抜ける（ステップアウト）
- `continue` / `c`: 次のブレイクポイント / 終了まで進む

## Ruby コマンドの実行

ブレイクポイントで止まったあとは irb 同様に Ruby のコマンドも使用可能です。
特定の変数の内容を確認したり、任意の Ruby コードを実行できます。

```
pp user
```

## 新たなブレイクポイントの設定

`break`（または `b` ）コマンドを使用すると、ファイル修正して再実行の手間を省いて次のブレイクポイントを設定することができます。

### 行指定でブレイクポイントを設定

```
b 123
```

ファイル指定も可能

```
b users_controller.rb 123
```

### メソッド指定でブレイクポイントを設定

```
b user.category
```

```
b User#hoge
```

### 条件指定でブレイクポイントを設定

```
b if: user.name.present?
```

### 特定の例外発生時にブレイクポイントを設定

```
catch StandardError
```

### ブレイクポイントを削除

```
del
```
