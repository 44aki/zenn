Inner Resource(以下、弊社)からは正社員のエンジニア全員(3名)がRubyKaigi2026に参加しました。Speakerでもスポンサーでもないのに、エンジニア全員で参加させてくれた会社には本当に感謝です。

私自身はRuby歴9年ほどですがRubyKaigiには初参加だったため、感想なども交えながらRubykaigi2026を振り返ってみたいと思います。

# Day1

## The Journey of Box Building

https://speakerdeck.com/tagomoris/the-journey-of-box-building

初日のキーノートは Ruby 4.0.0 でリリースされたメイン機能の一つである Ruby Box についての内容でした。

RubyKaigi2026 に参加した際も、ちょうど Ruby および Ruby on Rails のバージョンアップ作業を行なっている最中だったので、Ruby 4 にバージョンアップしたら早速 `Ruby::Box` を触ってみようと思います。

その他、印象的だったのは Ruby Box の内容自体よりも、Rubyコミッターの Satoshi Tagomori 氏が RubyKaigi 2023 Day2 の Multiverse Ruby のセッションを見て、今まで自分がRubyの開発に関わることはないと思っていたところから、一夜にして Ruby Box を開発したいと思い立ったエピソードでした。

今回の RubyKaigi 2026 の各セッションの中でも Ruby の改善ポイントやアイデアが紹介されており、今回の RubyKaigi のセッションを起点として、また次の Ruby コミッターが生まれるのかも知れません。

## Exploring RuboCop with MCP

https://speakerdeck.com/koic/exploring-rubocop-with-mcp

弊社でも今年になってからちょうど Rubocop を導入したタイミングだったため、気になっていたセッションでした。

MCP Ruby SDK のコミッターでもある Koichi ITO 氏が rubucop にどのように MCP を取り入れるかという内容でしたが、rubucop の情報は既に一般的に沢山出回っているため、MCP 化しなくても、既に AI が rubucop を理解していたという話は面白かったです。

最近では MCP よりも Agent Skills や CLI 化の流れが主流になっていると思いますが、流れの早い AI に無理に対応させるよりも、まずは本体自体の性能や使いやすさを洗練させていくことが重要に思いました。

# Day2

## Twenty Years of JRuby

２日目のキーノートは JRuby が誕生してからの20周年の振り返りと、JRuby 10.1 のリリースについての内容でした。

業務では CRuby しか使ってこなかったため、JRuby についての知見はほとんど無かったのですが、JRuby が CRuby よりも速いというのは意外でした。

JRuby が CRuby よりも一般的に使われていない理由の一つが既存の C 拡張ライブラリを使うことができないということかと思いますが、CRuby が C 拡張にも対応しつつ、JRuby よりも早くすることができるのか、今後の Ruby の進化が楽しみになりました。

## Surviving Black Friday: 329 billion requests with Falcon!

2025年のブラックフライデーにピーク時には毎分8500万件ものリクエストをどのように捌いたかというお話。

エンジニアとしてはこういうのを聞いているとワクワクしてしまいます。Falconは試してみたいものの、採用事例があまりないのは何故なんでしょう。。

## Practical TypeProf: Lessons from Analyzing Optcarrot

https://speakerdeck.com/mame/practical-typeprof-lessons-from-analyzing-optcarrot

弊社では RBS や TypeProf は今のところ採用していませんが、型がない Ruby は AI 的にはむしろトークン効率が良いという実験結果（実験結果に対する異論もありますが）もあり、今回のセッションを聞いた上で、やはりまだ型の導入は様子見で良いかなと思いました。

# Day3

## Ruby Committers and the World

![Ruby Committers and the World](/images/1000006843.jpg)

Rubyコミッター等が壇上で公開ディスカッションする恒例のイベント。

AIについてのトピックが多かった印象で、Matzが最近はmrubyの開発を100%AIで行なっているというのは驚きました。

Matzに限らず、コミッターはほぼ全員rubyの開発にAIを使っており、「ちゃんとAIのコードをレビューしているよね？」と釘を刺すような場面があったのも印象的でした。

## Smalruby: Visualizing Ruby with Bidirectional Transpiration

https://docs.google.com/presentation/d/1EWFcFLN122gNJj4mfRUGUqPDELqaLW17juMSv7OvhKk/edit?slide=id.slide_title#slide=id.slide_title

SmalrubyとはScratchベースをベースに、Rubyを視覚的に学ぶことができるようにしたもので、私は今回のセッションで初めて知りました。

自分の子供がもう少し大きくなったら、プログラミングを教えたいのでその参考にセッションを聴いてみようと思っただけでしたが、初めての言語としてRubyを学んでもらうことの重要性や、AI時代にプログラミングを学ぶことの意味などを改めて考えさせられるセッションでした。
